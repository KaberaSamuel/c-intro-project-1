# Project Instructions

## Assignment folders

Keep every assignment in its own folder under `assignments/`. Each assignment folder must contain its source code, output screenshots, and a `README.md` explaining the work.

Use this layout:

```text
Project 1 Assignment/
├── AGENTS.md
├── README.md                 # Project overview and links to the assignments
├── assignment.md             # Full assignment requirements and grading benchmarks
└── assignments/
    ├── water-quality-monitoring-system/
    │   ├── README.md
    │   ├── src/
    │   │   └── main.c
    │   └── screenshots/
    │       └── output.png
    ├── mobile-money-transaction-system/
    │   ├── README.md
    │   ├── src/
    │   │   └── main.c
    │   └── screenshots/
    │       └── output.png
    ├── delivery-route-analysis/
    │   ├── README.md
    │   ├── src/
    │   │   └── main.c
    │   └── screenshots/
    │       └── output.png
    └── smart-parking-system/
        ├── README.md
        ├── src/
        │   └── smart_parking.ino
        └── screenshots/
            └── simulation.png
```

- Name assignment folders after their topic, without question numbers or a `question-` prefix. For example, use `mobile-money-transaction-system`.
- Keep each assignment's code, explanation, and evidence in its own folder.
- Save additional screenshots in that assignment's `screenshots/` folder with clear names, such as `available-space.png` and `occupied-space.png`.
- The root `README.md` should give a short project overview and link to each assignment folder.
- Each assignment `README.md` should briefly describe the solution, how to run or simulate it, and what its screenshots show.
- Use the filenames and extensions that fit the language and tools for the assignment. Do not put screenshots in the source-code folder.

## Writing and code style

- Write README files and code comments in simple, short, natural language.
- Avoid AI jargon, overly formal or complex wording, and em dashes. Use a comma, colon, or full stop instead.
- Keep comments brief and useful. Explain the reason for a non-obvious choice rather than restating the code.
- Prefer the simplest readable solution that meets the assignment requirements and grading benchmarks. Avoid clever or complicated approaches when a clear, direct approach works.
- Keep the code organized and use clear names so a beginner can follow it.
- Simplicity must not leave out required features or reduce correctness. Follow the assignment requirements and aim for the highest rubric level.
